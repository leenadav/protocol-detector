Answers Hermes on PRO-505 (SEC-CHILD-4): `matchPattern` in `go/internal/childapp/childapp.go` split the whole path for every pattern, so a 4 KiB path of 2,048 segments cost about 270 µs and 233 KB on the embedded Graph rules (44 patterns after SEC-CHILD-3) and 8.9 ms and 8.5 MB against 256 patterns on one host (local benchmarks, go1.27.4). The path is now split once per request, lazily, into at most 33 parts, and once more only for a case-folded rule on a path with upper case; a pattern compares the segment count first; `canonicalPath` finds dot segments without splitting; and the loader refuses more than `MaxPatternsPerHost` (256) path patterns under one host or host suffix (the embedded data peaks at 44, on `graph.microsoft.com`). They now cost about 15 µs and 10 µs, under 1 KB each (`BenchmarkClassifyGraphLongPath`, `BenchmarkClassifyPatternCapLongPath`). Matching is unchanged: randomized tests compare the new matcher with the old one (32,000 pairs) and the dot-segment scan with the old split (20,000 paths); `TestPatternWorkSplitsOncePerRequest` pins at most one split per request. Docs: `docs/CHILD-APPS.md`.
