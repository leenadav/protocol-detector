go/cmd/protodetect/main.go declared const version = "0.0.0-m4", and the linker silently ignores -ldflags "-X main.version=..." on a constant, so a release binary named protodetect-<release>-... still reported 0.0.0-m4 (PRO-26 review, P2). It is now var version = "0.0.0-m4": same default, no output or parity change, no Python change. Test first: TestVersionIsSettableAtBuildTime (go/cmd/protodetect/version_test.go) did not compile against the const and passes now; it checks the default and that the version command prints a stamped value. CI errcheck then flagged unchecked pipe Close calls in that test; d89f332 checks them (tools/go_lint.py: no finding beyond the baseline, 194 accepted). A manual go build -ldflags "-X main.version=2026.11.26-test" prints the stamped version; a plain build prints 0.0.0-m4. Open: PRO-194 (Platform & CI) adds the -X flag to the release build and checks the binary's version output.
