The loader checked a `host_suffixes` entry only against the owner of the suffix itself (`go/internal/childapp/load.go`, `addRule`), so `googleapis.com` under `google-base` loaded although the catalog gives `maps.googleapis.com`, `play.googleapis.com` and others to other applications; only the match-time owner check of SEC-CHILD-2 (`Classify`) kept those hosts out of the child. Now `Load` indexes every catalog service domain under each of its parent domains once (`nestedDomains`), and a suffix with a nested domain whose owner is neither the container nor a `depends_on` is refused, naming the domain and its owner. The `Classify` re-check stays as the second layer. Web fronts under a suffix need no load check: `Classify` refuses a web-front host before any rule. No shipped child uses such a suffix (`TestShippedSuffixesHaveNoForeignOwners`); `TestSuffixRuleStaysInsideItsOwner` now names `www.googleapis.com` exactly. Tests: `secchild5_test.go`. PR #201 (`548f477`) fixed the same finding independently; PRO-604 merged `main` into it, keeping `main`'s code and adding PR #201's extra tests there.
