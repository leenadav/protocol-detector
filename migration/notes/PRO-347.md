Each task now adds migration/notes/PRO-<n>.md instead of editing the shared ledgers. tools/build_ledgers.py (stdlib, deterministic) writes the marked "Recent work" sections of both lane briefs and STATUS.md from the notes plus git log (the pull request that merged each note), and the README/REVIEW-SCOPE test counts from tools/check_docs_counts.py. The ci `ledgers` job fails on a hand edit or a malformed note and lets a pull request's own note lag; check_docs_counts.py fails on a lagging test count only with --strict (release gate, nightly job). The nightly ledgers workflow runs the strict check and uploads the refresh patch read-only; opening the refresh pull request itself needs Lee's policy decision (write token). Two branches that each add a note merged with no conflict (self-test and a real trial merge).
