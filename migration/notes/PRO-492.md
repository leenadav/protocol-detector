Enterprise App-ID: a service splits into child apps per function; the verdict names both (app=gmail-uploading, container=gmail). Go only. go/internal/childapp matches one proxied HTTP request on host, method, path prefix or pattern ({name} placeholders, no regex), query, headers present, content type, direction and WebSocket; the most specific rule wins. Rule hosts must be claimed by the container or its depends_on; non-canonical paths and SNI/Host of different owners never match. Ceiling: host index, 64 rule evaluations, 4,096 path bytes, reported in `limit` (PRO-477). API: go/detector AppClassifier; policy.FromJSONWithChildren adds a Go-only `containers` key. Rules are generated by tools/child_apps_wave.py from App Research's cited wave 0 (PRO-495, branch -b 5ebe8f5, copy in migration/fixtures/child-apps): 47 children over 20 services, 3 skipped (docs/child-apps/wave-0-rules.md); make check verifies the conversion. The pack stays at 2026.11.9 (frozen answers pin it). Tests: examples, refusals, rapid oracle properties (mutation-checked), two fuzz targets. Later waves: PRO-491. Parity 7,474 of 7,474.

SEC-CHILD-2 (PRO-505, answered on PRO-509): a child match moved a request out from under its host's catalog owner, so `deny containers:[ms-base]` allowed Graph sendMail and `containers:[google-base]` Gmail send and Drive uploads. Fix: `Result.HostOwner` / `AppVerdict.host_owner` / `appid.Verdict.HostOwner` (Go only, never serialized by the reference paths) carry the server name's catalog owner; policy `containers` and `AppVerdict.Matches` also match it; a rule fires only when the request host's owner is the child's container or a depends_on (a `host_suffixes` rule under google-base no longer fires on google-maps' maps.googleapis.com); a child's risk defaults to the highest of its container's and depends_on's, and a lower explicit risk is refused. Tests: go/internal/childapp/owner_test.go (four tests, red before the fix).
