SEC-CHILD-1: a refused, capped or ambiguous child-app request fell back to the parent like one no child applies to, so "deny gmail-uploading" was bypassed by %6f, a repeated or encoded query parameter, //, ./ or an oversized path or content type. Fix in go/internal/childapp on PR #163's branch (head dadc6bd): every verdict carries child_status (matched, none, undetermined, not_applicable); undetermined is fail closed and set for path_not_canonical, every limit and the new request_ambiguous reason (a repeated query parameter, an unparsable content type or a trailing slash on a pattern, only when that rule would win). A host with no child rule stays none. Escapes of unreserved bytes are decoded in path and query before matching (RFC 3986 6.2.2). Policy: Go-only child_status key in FromJSONWithChildren; go/detector AppVerdict.child_status and AppClassifier.MayBe for deny entries. Gmail's API host belongs to google-base, so a deny needs apps [gmail, google-base] with child_status undetermined until SEC-CHILD-2 carries host_owner. Path case variants are SEC-CHILD-3.
