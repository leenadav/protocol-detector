`tools/check_security_requirements.py` kept only lines matching ROW, so a row with free text ("manual review"), prose after the backtick or a missing cell was dropped with rc=0, and duplicate or deleted ids went unnoticed (`main` had SR-58..SR-63 twice). Now every line holding `|` must be the header, a separator or a strict `| SR-n | requirement | `refs` |` row (ASCII id, no leading zeros), so a row without its leading pipe or with a Cyrillic or fullwidth id fails too (SEC-PYRM-10); so does a pipe-less line starting with an id-like token. Duplicate ids and an id set differing from `tools/security_requirements.lock.json` fail; `--write-lock` pins ids and drops one only with `--retire`. The newer duplicates are SR-70..SR-75. `--self-test` (27 cases) runs in `make requirements`. The lost unpushed `b8a594e` is redone as `b80580f`. Out of scope: SEC-PYRM-2, SEC-PYRM-4.
