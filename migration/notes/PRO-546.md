`tools/check_security_requirements.py` accepted a Python reference that named any `def` (a helper too) or only a module, and `--run` ran only the Go tests, so SR-63 and SR-67 counted as verified while their tests were never run; without `go/bin/protodetect` the SR-63 test skips and an SR-67 test errors, and the old gate still returned 0. Python references must now be `<dir>/test_<name>::test_<method>` with a `def test_<method>(self` in the file (a bare module, a non-`test_` function or a `..` path is refused), and `--run` runs each referenced method in a fresh interpreter per module; a skip (class-level and subTest too), expected failure, unexpected success, failure, error, import error or a name with no TestCase method fails. The CI `security-requirements` job now builds the Go binary first (`tools/go_ci.py build`, as `publish-release.yml` does) and `make requirements-run` depends on `go-build`. Self-test: 5 new reference cases and a runner case of 9 outcomes. Stacked on PR #174 (PRO-403, the only branch with `--run`); conflicts with PR #178 (SEC-PYRM-1) in the same file. SEC-PYRM-4 (Go outcomes via `go test -json`) stays out of scope.
