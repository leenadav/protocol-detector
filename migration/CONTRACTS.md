# Migration contract matrix (M1)

The behaviours a second implementation must reproduce, each anchored to the Python reference, the
documents that define it and the differential cases that check it (`migration/fixtures/cases.json`,
generated by `migration/parity/cases.py`, compared by `migration/parity/compare.py`). Python is the
reference for *supported* semantics; a disagreement is settled against PROTOCOLS.md and recorded as an
approved delta in `migration/parity/deltas.json` (one path of one case, with a justification), never by
widening the comparison's tolerance. Go status for every row is `pending` until the harness proves parity.

Vocabulary that must not change: statuses `detecting · identified · unknown · malformed · incomplete ·
budget_exhausted · invalidated`; event kinds `updated · refined · shifted · invalidated · datagram`;
evidence `(field, value, source, strength)`; scopes `initial_message` and the continuation/shift scopes
the Python model emits; session `engine_status`, `decision`, `attribution`, `layers`, `unknown`.

## Harness proof (M1 exit gate)

- `python3 -B migration/parity/compare.py --backend python` on the committed cases: 1366 compared, 1366
  matched, 0 mismatched, 0 missing, 0 exempted.
- Planted regressions, each reported as a mismatch on the case it touched: `wrong-positive` (an unknown
  stream becomes identified), `missing-retraction` (an invalidated session record becomes identified),
  `wrong-port` (a server port moves), `dropped-event` (an intermediate event disappears), `boundary-shift`
  (`bytes_inspected` moves). `test_migration_parity.py` runs all five on every `make check`.
- Determinism: the generator is seeded; two runs produce identical inputs and expectations.

## Not canonicalized (compared verbatim)

Statuses, protocols, applications, hostnames, reason sentences, evidence tuples and their order, event
kinds and order, revisions, metrics, directions, per-packet adapter messages, record fields, end reasons.

## Canonicalized

`content.digest` → `content.version` only. No wall-clock values exist in the compared paths (capture
timestamps are inputs and kept); no generated identifiers appear in engine or adapter output.

## Performance comparison

Separate from parity: `migration/benchmarks/` holds the Python baselines (`benchmark_engine`,
`perf_profile`); Go numbers are compared relatively on the same host in M9, never as a parity signal.
