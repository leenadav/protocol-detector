# Security requirements

Each requirement names the test(s) that verify it. `tools/check_security_requirements.py`
fails CI when a referenced test no longer exists, and with `--run` (`make requirements-run`,
the CI `security-requirements` job) when a referenced Go test does not PASS on the pinned Go
or a referenced Python test method does not pass (a skip, expected failure, error or missing
method fails; PRO-546).
Format of the last column: `go/<package dir>::TestName[, ...]` for a Go test or fuzz function,
or `<dir>/test_<name>::test_<method>` for a unittest method of the repository's Python tooling
(a bare module or a non-`test_` function is refused).

PRO-403 removed the Python reference engine and the Python tests that verified these rows (the
tag `python-final` keeps them). The protocol-profile rows are now verified by
`go/internal/replay::TestSR*`, which replay two frozen sets of the reference's answers through the
Go engine and fail on any difference: `migration/fixtures/requirements.json.gz`, every inspector
input the row's former Python tests made (recorded per test at `python-final` by
`migration/parity/requirement_cases.py`), and the `migration/fixtures/cases.json` cases of the
families the row names. Bounds no recorded input sits on have their own Go tests. A mutation of
each numeric bound these rows name fails at least one of the listed tests (PRO-403 note).
