# Security requirements

Each requirement names the test(s) that verify it. `tools/check_security_requirements.py`
fails CI when a referenced test no longer exists, and with `--run` (CI and `make requirements-run`) when a
referenced Go test does not pass. Format of the last column: `go/<package dir>::TestName[, ...]` for a Go test
or fuzz function, `<python module path>::test_function` for the remaining Python (the presentation launcher).

PRO-403: the Python reference engine and its tests were removed (tag `python-final`). Every row was re-pointed
to Go tests, and each row's guard was mutated in the Go code to prove that at least one named test fails without
it; the mutations, the tests added for them and the remaining gaps are in
[docs/security/SR-GO-EVIDENCE.md](docs/security/SR-GO-EVIDENCE.md). Three clauses (SR-32 policy lint, SR-67 corpus
harness, SR-69 minimizer) describe Python-only tools with no Go counterpart; they are marked as gaps, pending a
decision, and SR-67 fails the gate until it is decided.
