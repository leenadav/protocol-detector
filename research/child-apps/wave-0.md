Rule-field policy:

- signals hold only facts read in the cited official document (vendor API reference, vendor's own SDK or spec repository, vendor network page, or the git project's protocol document).
- Anything inferred, unread or opaque (a URL returned at run time) is in notes or not_separable, never in signals.

- Precedence inside a parent: the most specific child wins (more signal fields matched); base is the fallback.

## Host notes for Engine

- **Gmail**: gmail.googleapis.com is not in pack app_domains[gmail]: today it matches google-base (googleapis.com). The children need Engine to map this exact host plus path to gmail.
- **Outlook.com**: graph.microsoft.com is not in app_domains[outlook-web]: today it matches ms-base (microsoft.com). Graph serves every Microsoft 365 workload, so the parent comes from the path, never the host.
- **Google Drive**: www.googleapis.com is shared by many Google APIs and today matches google-base; the parent comes from the /drive/v3/ or /upload/drive/v3/ path.
- **OneDrive**: graph.microsoft.com is not in app_domains[ms-onedrive] (today ms-base); parent from the path.
- **Dropbox**: content.dropboxapi.com and api.dropboxapi.com are already under dropboxapi.com in the pack.
- **Discord**: The gateway WebSocket host comes from GET /gateway at run time; its name was not taken from a page here, so it is not listed.
- **YouTube**: youtube.googleapis.com is under googleapis.com, today google-base: parent from the path.
- **ChatGPT**: The API children have parent openai-platform (a separate pack id), not openai-chatgpt.
- **Gemini**: Parent google-gemini-api is the id proposed in batch G (research/apps/google-gemini-api.md), not yet in the pack; today generativelanguage.googleapis.com matches google-base.
- **Google Docs**: docs.googleapis.com is under googleapis.com, today google-base.
