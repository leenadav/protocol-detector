What you can demonstrate

  • Protocol identification from payload structure
  • Session-level application verdicts and port checks
  • Protocol changes at supported structural boundaries
  • Handshake fingerprints and advisory risk signals
  • Honest unknown and incomplete outcomes

How to read the results

  • Replay is a visualization of analyzed capture records.
  • Signals and catalog risk are not a threat verdict.
  • TLS offers do not authenticate application identity.
  • Live capture is passive; this UI does not enforce policy.
  • Processing time is local replay work, not SWG latency.

Source & processing limits

Uploaded captures are processed in a temporary local file, removed after analysis. The dashboard uses no external services, fonts or analytics.

From encrypted transport to application evidence

TLS 1.2 ECDHE-RSA AES-GCM · TLS 1.3 AES-GCM / ChaCha20-Poly1305 · supplied browser keys

Choose a complete IPv4 capture from the TCP handshake and its SSLKEYLOGFILE. Matching handshake and application secrets for both directions are required. Secrets are processed in a temporary worker, not saved or returned. Application labels use the existing engine catalog.

No decryption performed.

POC limits: 8 MiB capture, 64 TCP connections, 256 KiB per direction, 25 seconds. CBC, TLS 1.0/1.1, QUIC, 0-RTT and HelloRetryRequest are not supported. No proxy interception or certificate trust validation. Raw plaintext is not displayed.
